The agents

Ten roles, all played by Claude Code. Click an agent to see its model and what it does.

02

Intake and scheduling

A ticket arrives through pasted URLs or through the file vigie keeps up to date. The console decides when it may start, then opens a Claude Code session in a dedicated worktree.

03

04

What runs during the whole run

Every tool call of the session goes through the hooks before it reaches the console. The safety rules are decided there, not in a prompt.

05

After the final report

The MR waits for the engineer's review, the queue is released at the merge, and the factory audits itself only when it observed something going wrong.

  metrics{"run-metrics-runtime.ts

  settle{"run-worktrees.ts

  audit{"self-improvement.ts

  improve["Session /improve

  rebase["Session /rebase

  auto{"auto-merge.ts

  judge["Session /judge-improvement

  restart{"impl restart

  done --> metrics --> settle
  done --> sweR
  sweR -- "change requested" --> reopen --> devR --> review --> sweR
  sweR -- "merge" --> watch --> queue
  done --> audit
  sweF --> audit
  audit -- "incident, failed criterion,
abnormal cost, feedback" --> improve
  audit -. "nothing observed:
no session" .-> stop(("end"))
  improve -- "main moved,
git alone cannot rebase" --> rebase --> auto
  improve --> auto
  auto -- "passes" --> judge
  auto -- "rejected" --> retry
  judge -- "rejected" --> retry
  retry -. "next run,
2 attempts at most" .-> improve
  judge -- "merge,
console/ or bin/ changed" --> restart

Models read from the frontmatter of agents/*.md and commands/*.md, and from console/server/engine/claude-code.ts. At tiers 0 and 1, the pilot runs Senior and QA on Sonnet; they keep Opus at tier 2. The Designer runs on Sonnet at every tier. The Dev runs on Sonnet, and the pilot moves it to Opus for a task the plan sizes L. The machinery underneath, from the path of a hook to the evidence chain, is on the architecture page. The page loads Mermaid and its fonts from a CDN, so it needs a connection.
